# Changelog

All notable changes are listed here, newest first. Version numbers follow `MAJOR.MINOR.PATCH`.

## Unreleased

- **Licences:** `THIRD_PARTY_NOTICES.md` lists the bundled components with their versions and licences (generated by
  `python tools/gen_notices.py`); it is installed with the Windows app and the Linux packages.
- **Project:** the tests also run on Python 3.10 and 3.14, pyflakes runs in CI, CodeQL analyses the code every week, every GitHub
  Action is pinned to a commit, and there is an issue template for translation corrections.
- **New: speed limit, allowed hours and proxy** (Settings). The limit applies to each of the simultaneous downloads; outside the
  allowed hours nothing new starts (what is already downloading finishes; a window like 22:00 to 06:00 goes through midnight); the
  proxy (`http`, `https`, `socks4`, `socks5`) is used by the downloads and by the reading of the lists.
- **New: Pause all / Resume all** in the list of downloads, and in the choice of the videos of a playlist **Invert selection** and
  **Select a range** (for example `1-20, 25, 30-35`). All texts are translated in the 16 languages.
- **Security: downloaded components are verified.** ffmpeg, deno and yt-dlp are checked against the SHA-256 published by their makers
  and a file that does not match is never used; if the list cannot be read a warning is said (set `YTG_REQUIRE_CHECKSUMS=1` to refuse
  instead). The Termux installer served from the computer also carries the SHA-256 of the zip and the phone refuses a different file.
- **Fix: two videos that finished at the same moment could still take the same file name** (the second overwrote the first): choosing
  the name and taking it is now one step. Found by the new tests of the whole pipeline.
- Tests: the download pipeline is now tested end to end without the network (a fake worker and fake lists): numbering, errors,
  retries, the limit of 10 downloads, cancelling, choosing the videos, resuming after a restart and the HTTP API (13 tests).
- **Security: an access token for the page.** When it is set, every request except the ping needs it (cookie `ytg_token` or header
  `X-YTG-Token`); the link with `?t=<token>` starts the session. It is on by itself with `--host 0.0.0.0` (`--no-token` turns it off) and
  can be asked for with `--token` (the token is kept in the data folder, readable only by the owner, so the link stays the same). The Android
  app now always uses a token of its own, new at every start: all the apps of a phone share `127.0.0.1`, and any of them could use the
  downloader before. Tested in an Android 14 emulator.
- **Failures are told by the type of the exception first** (geo block, live stream, conversion, network, HTTP 429/5xx) and by the words
  of the message only as a fallback: yt-dlp rewords its messages, its exception types change rarely.
- **With very long playlists the list of downloads is saved less often** (every 2 seconds up to 10,000 videos, then proportionally, at most
  every 30): rewriting 8 MB twice a second was wasteful.
- Code: `do_POST` is now a table of routes and `job_action` a table of small functions (both had a complexity of about 48).
- A worker process that has been stopped is now collected (on Linux and macOS it stayed as a zombie until the program ended).

- Maintenance, nothing changes for users: `CLAUDE.md` (notes for whoever continues the work), `docs/ROADMAP.md` (what to do next),
  `tools/check.py` (all the checks in one command), `tools/verify_release.py` and `tools/update_channels.py` (the end of a release),
  `requirements-dev.txt`, `.editorconfig`, a documents-links step in CI, and the description and topics of the GitHub repository.

## 1.6.1

A review of the whole program found these problems; none was reported by a user.

- **Fix: two different videos with the same title overwrote each other** (in the *Singles* folder, where the files have no
  number): the first file was lost and both showed as completed. The second one now gets ` (2)`.
- **Fix: a video called exactly `CON`, `NUL`, `AUX`, `PRN`, `COM1`…`COM9` or `LPT1`…`LPT9`** produced a file that Windows cannot
  create. These names now get a `_` in front.
- **Fix: a request with a wrong `Content-Length`** gave an internal error; it is now refused with a clear one.
- **Fix: with a long list, every tick in *choosing the videos* downloaded the whole list again**; now only what changed.
- **Security:**
  - Other devices on the network (`--host 0.0.0.0`) can no longer choose another destination folder or upload cookies.
  - The page is served with a Content-Security-Policy, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer`; for that, the
    two small scripts of `index.html` moved to `boot.js` and `langload.js`. The files that were downloaded are served with a
    sandbox policy.
  - The server no longer tells its name and version, and closes connections that stay idle for two minutes.
  - The cookies file and its copies, and the data folder, are readable only by the owner (Linux and macOS).
  - The one-click update only accepts an installer with the expected name and refuses a temporary folder whose name contains
    characters that `cmd.exe` would interpret.
- **Windows:** the file properties of `YT-Grabber.exe` (description, language) were in Italian; they are now in English.
- The settings picture and the README sentence about what the program connects to were brought up to date.
- Tests: 20 new ones, among them the first tests of the HTTP server (headers, refusals, what only the local computer may do).

## 1.6.0

- **Choose the videos of a playlist:** *Let me choose the videos first* reads the list and waits; untick what is not wanted (all or
  none with one press, or one by one, also with the keyboard: arrow keys and Space) and press *Start*. While a download runs, any
  video that is still waiting can be skipped, and a skipped one can be added back. Skipped videos have their own tab.
- **Code reorganised:** `server.py` no longer holds everything. The settings, `Item` and `Job`, the links and file names, and the
  updates are in `ytsettings.py`, `ytmodel.py`, `ytlinks.py` and `ytupdates.py`; the tests are split into one file per subject
  (`tests/README.md`); `program/README.md` describes the modules. Nothing changes for users.
- The Android build now includes every `*.py` of `program/`, so a new module needs no change there.
- Links inside the hints of the settings window (the new Android hint has two) use the accent colour and an underline, so they stay
  readable in the dark theme and in forced-colours mode.
- A playlist that was waiting for the user's choice when the program was closed continues reading its list when the program starts again.
- Documentation: a new picture for choosing the videos, and a settings picture that shows the current options.

## 1.5.1

- Documentation: the accessibility statement now records the tests with the NVDA screen reader.
- Screen readers (found by testing with NVDA): the button that changes the destination folder is announced with its context
  instead of just "Change"; the box for the links no longer reads a long description at every visit; the Tab key lands on a single
  item of a list instead of making the screen reader read the whole list; and the language of the user is loaded before the page is
  shown, so the page is not read once in English first.
- The hint for Android phones in the settings pointed to folders that no longer exist (`APK`, `termux`); it now links to the releases
  page and to the installation guide, in all 16 languages.
- On the web page, the *Update yt-dlp* controls (including the new automatic option) and their hints are hidden together when the
  page is not opened on the computer that runs the program.

## 1.5.0

- **Update now (Windows application):** the new-version notice offers a button that downloads the installer from the releases,
  verifies its SHA-256 fingerprint, closes the application, installs the new version and reopens it. The button is not shown for
  installations made with Scoop, winget or Chocolatey.
- **Android:** a notification is shown when a download finishes (it can be disabled in the settings).
- **Arrow keys in the list of items** (Up, Down, Home, End, Page Up, Page Down), with a single Tab stop for the whole list.
- **Settings → Text size** (100% to 200%).
- The tick mark inside the selected option is no longer read by screen readers as part of its name.
- **Automatic yt-dlp updates:** once a day the program checks the latest yt-dlp and, when nothing is downloading, installs it and
  restarts by itself (*Settings → Download engine*, enabled by default). The same version is never installed twice in a day.
- **Android build tools updated:** Android Gradle plugin 9.5 (built-in Kotlin), Gradle 9.6.0, compileSdk 37, androidx core-ktx 1.19.1
  and appcompat 1.8.0. The application is also compiled by CI at every change.

## 1.4.0

- **Accessibility (WCAG 2.2 AA):** the whole interface was reworked and is now checked automatically at every change.
  Keyboard: skip link, genuine buttons, a settings window that retains the focus and returns it on closing, and a focus that is
  preserved when the page refreshes. Screen readers: names and states for every control, switches, progress bars, a list of items
  with positions, announcements when a download finishes or fails, and labelled groups and regions. Visual presentation: colours
  with sufficient contrast in both themes (the accent colour is darker), control borders at 3:1, marks in addition to colour,
  text sizes in `rem`, zoom up to 400%, 44-pixel touch targets, forced-colours and increased-contrast modes, and no animation when
  "reduce motion" is set. Messages in the corner can be closed and remain visible while they are being read. Android: pinch zoom,
  the system font size, and a start-up screen that screen readers can follow. Windows: a sharper start-up window.
  See [docs/accessibility.md](docs/accessibility.md).
- Downloading ffmpeg and the other tools at the first start now **retries** when the connection is interrupted (a weak network
  could previously stop the setup).
- **Repository reorganised.** The build folders are now under `packaging/` (`windows`, `android`, `linux`, `macos`, `termux`), the
  results of local builds go to `dist/`, the public signing key moved to `docs/release-key.asc`, and each `build-*.bat` is now
  `build.bat` in its folder. Nothing changes for users who install a release.
- **Documentation rewritten:** a shorter README; guides in `docs/` (installation, usage, development); `CONTRIBUTING.md`; a README
  for each folder in `packaging/`; and issue and pull request templates.
- `tools/bump_version.py` sets the version in every file that carries it (covered by a test).
